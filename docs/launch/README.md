**OG game**: branch `OG-game`, commit `be79b2141106c5b86c607a12bff7a1df0266434e`. The existing Vercel site and its database were not changed. The separate launch branch uses a fresh Supabase development project (`xapmfidxhutwlvmdjdao`), even when the host supplies production environment variables. New preview accounts are independent. See OG-game.json; a tested full production data backup is still needed before any production cutover.

## Try it
Open **Clubhouse** on Home or your own Profile for the shop, inbox, private courses, and submissions. Create a friend course, play three holes, invite an accepted friend by code, or remove access. It has its own leaderboard and never enters public crown counts. A new public submission stays out of the map and cannot be challenged until approved. An administrator can inspect the pin, correct the name and publish or reject it. No player gets admin by choosing a particular name.

Fresh capture: lower score wins; a tied score must have strictly better time. At exactly 48 hours any tied score wins; at 72/96/120 hours allow one/two/three extra strokes, capped at three. Time alone never changes the owner. A successful challenge or a new completed defense by the owner starts a fresh clock. The map shows the current capture target and permanent record separately.

## Passes and store
One remote attempt costs one pass, for a previously visited public course only. Maximum three starts per Eastern day. Confirm the course before taking the pass, reuse the request UUID on network retries, and consume the pass if the player concedes. Completing a verified round can earn two passes once per Eastern week. Support can restore a pass after verifying a technical failure using `refund_failed_attempt`; it rejects completed rounds. Private rounds do not earn global rewards.

The native StoreKit bridge starts checkout with the signed-in player's app account token; a signed Apple transaction must pass server verification before the wallet or entitlements change. Notifications of refund or revocation reverse fulfillment. Browser checkout is disabled. Create the following App Store Connect products for the *preview bundle*:

| Product suffix (prefix com.puttputtpotty.) | Type | Contents |
| --- | --- | --- |
| starter | Non-consumable | Clubhouse blazer, visor and pearl ball; two passes once |
| teleport3 | Consumable | Three passes |
| teleport10 | Consumable | Ten passes |
| royal_style | Non-consumable | Velvet uniform, coronet, crown jewel ball and amethyst cart |

Cosmetics can be selected in the avatar studio and garage; no physics changes. Do not accept a client receipt, fake credit or payment outside StoreKit as a way to test the real wallet.

## Native setup and gates
Run `npm ci && npm test && npm run build && npx cap sync ios`. Open `ios/App/App.xcodeproj` in Xcode, set your signing team and register bundle ID `com.puttputtpotty.game.preview` with Push Notifications and Sign in with Apple. Use the sandbox for purchases. Enable Apple and manual identity linking in **preview** Supabase Auth, allow its native bundle identifier and `puttputtpotty://auth/callback`, configure the preview web redirect and your email sender. Never copy production users into an open preview. Provision the preview administrator only after verifying the account owner out of band.

Configure secrets in the preview backend: APPLE_BUNDLE_ID, APPLE_STORE_ENVIRONMENT=Sandbox, APPLE_ROOT_CERTIFICATES_BASE64 (JSON array of Apple trust anchors), APNS_TEAM_ID, APNS_KEY_ID, APNS_PRIVATE_KEY, APNS_ENVIRONMENT and PUSH_SCHEDULER_SECRET. Point the App Store sandbox notifications URL to the staging function at `/functions/v1/potty/apple-notifications`. Set an authenticated scheduled POST to `/functions/v1/potty/deliver-push` (Authorization: Bearer plus the private scheduler secret); the worker respects local quiet hours and preferences. Daily and aging events are generated by the database scheduler.

Before TestFlight, check fresh install, guest-to-Apple/email linking, cold-start links, two-device identity, sandbox checkout/restore/refund, and notifications foreground/background/terminated on a signed iPhone. Browser and simulator builds cannot certify these. Production restore rehearsal, reliability fixes, store paperwork and submitting for review remain separate.
